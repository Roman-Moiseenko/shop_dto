# Шаблон API CRM Интернет магазина на чистой архитектуре

## Общее. 
### Доступы
Доступ определяется ролями. Базовые роли, которые разграничивают маршруты - admin, staff, client
Каждый модуль содержит системные роли разделенные по сущностям (возможно пересечение, объединение)
Например доступы для работы с клиентом (без учета доступа к User) создаем роль buyer с доступами:
 - auth.buyer.create,
 - auth.buyer.edit,
 - auth.buyer.view,
 - auth.buyer.delete,
 - auth.buyer.force,
 - auth.buyer.blocked.

Системные роли создаются через Seeder в каждом модуле.
Пользовательские роли создаются из доступов и назначаются сотрудникам. Системные роли не могут быть назначены.
### Обработка исключений
Исключения модулей обрабатываются в своих провайдерах, см. на примере **AuthServiceProvider**

## Модуль Share
### Интерфейсы
- MailServiceInterface - почтовый интерфейс, для отправки почты. При монолите прописан будет в модуле почты, при микросервисах отправка будет через очереди в Shared
- UserPermissionRepositoryInterface - интерфейс получения данных о доступе для пользователя, либо через Auth (монолит) либо через заголовки (микросервисы)

### Middleware
- LoadUserPermission - получаем доступы для залогинившегося пользователя. Данный мидлвейр применяется на все маршруты


## Модуль Auth
### Сущность User
 Сущность аутентификации. Может быть только в связке с сущностями пользователя.
 Кроме admin созданного через Консольную команду
 Все сущности могут иметь доступ к программе (иметь связанный User) или не иметь,
но User не может быть создан отдельно, через api.

### Сущность Staff
Сущность сотрудника, может не иметь доступа к программе, например логисты, которые учитываются в табелях и/или
могут иметь доступ к корпоративному боту для получения задач. 
При установке доступа, назначаются роли.
### Сущность Client
Клиента можно создать без доступа, через запрос из других модулей, например обработка Лидов и/или Заказов.
Если клиент регистрируется самостоятельно через форму на сайте, то создается помимо сущности Client, 
привязанный к нему User с ролью 'client'
### Сущность Freelance
Сущность с минимальными данными, для внештатных сотрудников. Роли назначаются отдельно для каждого.
Специальной роли для Freelance не предназначено
